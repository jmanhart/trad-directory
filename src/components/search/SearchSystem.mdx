# The Search System

A living map of every place a user types to find something in Trad Directory.
It's deliberately split into a **public** search (the marketing/site experience,
with a grouped suggestions menu) and an **admin** search (dense data tables).
This page is the source of truth — when a search surface changes, update it here.

> Status: this system drifted across iterations and is mid-consolidation. See
> **Roadmap** at the bottom for what's converging.

## Suggestions menu — `SuggestionMenu` & `SuggestionItem`

The dropdown behind `SearchBar` (and, soon, the admin autocompletes). A
`SuggestionMenu` is a `role="listbox"` of `SuggestionItem` rows; it's
presentational, so the parent owns the active row and key handling via the
exported `useSuggestionNav` hook (ArrowDown/Up wrap, Enter selects, Escape closes).

## Data & execution layer

The UI is thin; the search logic lives in a few shared modules:

- **`hooks/useSearchSuggestions`** — builds the `Suggestion[]` fed to `SearchBar`
  (artists + countries), consumed by the header, top bar, map, and home page.
- **`utils/suggestions`** — the `Suggestion` type and builders.
- **`utils/locationSearch`** — `classifyLocationQuery`, which detects when a query
  is really a location so results can show a map preview.
- **`utils/navigation`** — `createSearchHandler`, which routes a query to
  `/search-results?q=…`.
- **`services/api`** — `searchArtists` / `searchShops` (client-side filtering over
  the fetched dataset) powering the results page.

## Usage guidelines

- **Public, typeahead-with-suggestions?** Use `SearchBar`.
- **Filtering a table or list?** Use `SearchBar` in filter mode (`value` / `onValueChange`, no `suggestions`).
- **Don't** hand-roll a new dropdown — the shared **`SuggestionMenu`** primitive
  is the one accessible menu every autocomplete should use.
- Every search component ships a `*.stories.tsx` and is linked from this page.
